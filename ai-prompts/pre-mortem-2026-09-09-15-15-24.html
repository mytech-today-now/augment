Executive summary

The highest-confidence near-term breakages are already observable. The repository lint and TypeScript build pass, but the direct source CLI smoke path fails under Node 24 with a tsx transform error. The Vitest suite also has import and dependency drift, an orphaned mirror regression, timeouts in command integration tests, and a submodule fixture mismatch. These are not hypothetical design concerns: they are current signals that release validation and cleanup behavior do not share one reliable contract.

The next risk tier is boundary handling. Module resolution and file inspection accept paths that need explicit containment checks. MCP configuration can expose environment values when rendered as JSON, MCP child processes have no timeout or output budget, and skill execution enables shell interpretation of repository metadata. Those paths should be reviewed as security boundaries even when the normal local workflow is trusted.

Release posture:

Do not treat a green lint and build as sufficient release evidence. Before shipping a CLI change, establish one supported source and compiled execution path, make the relevant test harnesses agree on module ownership, and add failure-injection tests for cleanup, timeouts, drift, and partial writes.

Severity describes the user or release impact if the failure occurs. Likelihood describes how readily the current code or observed workflow can reach it. Priorities are ordered for engineering attention, not as a substitute for a product decision.

Assumptions are called out where a security finding depends on an untrusted caller or a configured value containing a secret. Those assumptions are testable: each implementation prompt requests a focused regression test that proves the boundary or documents the supported trust model.

Source CLI smoke path fails under tsx

Title
Source CLI smoke path fails under tsx
Kind
CoreRelease-blocking execution path
Priority
P1
Severity
High. A supported-looking command path cannot start, so users and the standalone harness receive no CLI behavior at all.
Likelihood
Almost certain. It reproduces now with npx tsx cli/src/cli.ts --help under Node 24.14.1.
Impacted area
cli/src/cli.ts, the test-all.ts source runner, package smoke commands, and developer onboarding.
Failure mode

Evidence or rationale

Why this matters
Build success can mask a broken developer and integration path. A release check that uses source execution will fail for the wrong reason, while a user who follows an obvious source command cannot even reach help or diagnostics.
Recommended mitigation
Choose one supported source execution contract, make the shebang safe for that runner or invoke the runner through a documented wrapper, and add a smoke test that executes the exact command on the supported Node versions. Keep compiled execution covered separately.
Implementation prompt
Resolve the repository root before editing. Inspect package.json, cli/src/cli.ts, test-all.ts, the TypeScript configuration, and the build output path. Use the observed tsx syntax error as the primary evidence. Preserve normal CLI dispatch, the executable shebang behavior after compilation, argument parsing, and the temporary-sandbox contract. Do not rewrite unrelated commands or replace the whole test harness. Implement the smallest compatible fix, then exercise expected errors such as missing commands, unexpected errors such as a loader mismatch, and a fallback copy or wrapper path if the preferred runner is unavailable. Preserve user state and avoid mutating installed packages. Add assertions for source help, compiled help, exit code, stderr, and one representative command. Include security and recovery checks for executing only the intended entrypoint, accessibility checks for readable diagnostics, and a rollback plan if the fix changes packaging or the public executable. Additional baseline tests

Acceptance criteria
The documented source smoke command reaches the dispatcher, compiled execution remains valid, expected bad input still fails clearly, and the standalone harness no longer reports the line-one transform error.
Confidence
High. The failure was reproduced directly and the relevant source-runner call sites are explicit.
